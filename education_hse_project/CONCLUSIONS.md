# Выводы исследования

Выводы получены на исправленных данных (разбор ошибок первых версий —
в [REPORT.md](REPORT.md)) и воспроизводятся командой `python run_analysis.py`.

Цель проекта формулировалась так: *отобрать математическую модель и
алгоритмы анализа логов, чтобы выявить паттерны работы учащихся*. Ниже —
ответ по каждой части.

---

## 1. Какая модель подходит задаче

`GGlevel` — **порядковая** метка из четырёх уровней, а не непрерывная
величина. Поэтому решается задача классификации, а качество измеряется
метриками, учитывающими порядок.

| модель | accuracy | macro-F1 | взвеш. каппа | MAE (уровни) |
|---|---|---|---|---|
| baseline «самый частый класс» | 0.332 | 0.125 | 0.000 | 0.845 |
| baseline «случайно по частотам» | 0.254 | 0.239 | −0.002 | 1.120 |
| **логистическая регрессия** | **0.552** | **0.562** | **0.672** | **0.500** |
| случайный лес | 0.532 | 0.540 | 0.643 | 0.513 |
| градиентный бустинг | 0.523 | 0.533 | 0.656 | 0.527 |

**Вывод.** Достаточно линейной модели: логистическая регрессия не уступает
ни случайному лесу, ни бустингу. Это значит, что связь признаков с уровнем
в основном аддитивная, а сложные взаимодействия между действиями заметного
вклада не дают. Для практики это удобно — модель остаётся интерпретируемой.

Взвешенная каппа 0.672 означает существенное согласие с истинными
уровнями; средняя ошибка — половина уровня, то есть модель почти никогда
не путает крайние категории.

Три разных семейства моделей упираются в accuracy 0.52–0.55. Похоже, это
**потолок данного набора логов**, а не недостаток конкретного алгоритма.

## 2. Ограничение: у 16 % респондентов лога фактически нет

Отдельный результат, который надо учитывать при любом использовании
инструмента. В выгрузке есть два **принципиально разных** вида пропуска,
и смешивать их нельзя.

**Сбой логирования.** У 14–16 % респондентов не записаны `fulltime`,
`openglasha`, `notion` и настройки сообщества. Доля таких записей по
уровням: 0.122 / 0.137 / 0.154 / 0.140 — **связи с уровнем нет**
(χ², p = 0.42). Это технический артефакт, а не поведение.

Для этих респондентов модель бессильна: на отложенной выборке она ставит
им всем один и тот же модальный класс, accuracy 0.341 — уровень угадывания.
На респондентах с исправным логом accuracy составляет **0.593**.

**Недоведение задания до конца.** Совсем другое дело: пустое поле с
адресом (38.5 % у нулевого уровня против 15.6 % у третьего), отсутствие
ответа на поздние задания `private6` и `wall4` (31 % против 14 %). Это
уже содержательный сигнал, монотонный по уровню.

> **Поправка к более раннему выводу.** В предыдущей версии этого разбора
> утверждалось, что главный предиктор — «факт завершения задания».
> Проверка показала, что это неверно в такой формулировке: индикаторы
> пропуска действительно занимают высокие места в permutation importance,
> но работают они как переключатель «здесь данных нет», а не как маркер
> компетентности. Удаление этих индикаторов почти не меняет качество
> (accuracy 0.552 → 0.548). Компетентность различает не сбой логирования,
> а недоведение до конца поздних заданий.

## 3. Паттерны работы, различающие уровни

Считано на 2403 респондентах с исправным логом.

| показатель | ур. 0 | ур. 1 | ур. 2 | ур. 3 | ρ с баллом |
|---|---|---|---|---|---|
| время выполнения, мин (медиана) | 9.3 | 10.6 | 11.6 | 11.6 | +0.067 |
| вызовов ассистента «Глаши» | 2.73 | 2.43 | 2.11 | 1.72 | −0.111 |
| ошибок при заполнении (`notion`) | 1.14 | 0.74 | 0.42 | 0.22 | −0.360 |
| проверено источников | 0.20 | 0.49 | 0.80 | 1.27 | **+0.482** |
| найден верный адрес | 34 % | 67 % | 87 % | 95 % | **+0.468** |
| скопирован только адрес, без контекста | 10.6 % | 12.5 % | 6.5 % | 2.6 % | −0.128 |

**3.1. Проверка источников — сильнейший поведенческий маркер** (ρ = 0.48).
Респонденты третьего уровня обращаются в среднем к 1.27 источника, нулевого —
к 0.20. Различает не столько правильность действия, сколько сама привычка
свериться с несколькими источниками, прежде чем ответить.

**3.2. Умение вычленить нужные данные** (ρ = 0.47). Верный рабочий адрес
находят 95 % респондентов верхнего уровня против 34 % нижнего.

При этом показатель «скопировал ровно адрес, без окружающего текста»
связан с баллом **отрицательно** (ρ = −0.13) и немонотонен: пик приходится
на первый уровень. Сильные респонденты копируют адрес **вместе с
контекстом** — то есть сохраняют информацию о том, чей это адрес и для чего
он предназначен. Аккуратность копирования сама по себе компетентности не
означает.

**3.3. Аккуратность заполнения форм** (ρ = −0.36). Число срабатываний
подсветки ошибок падает с 1.14 до 0.22.

**3.4. Самостоятельность** (ρ = −0.11). Число обращений к встроенному
ассистенту снижается с 2.73 до 1.72. Связь слабая: помощь запрашивают на
всех уровнях.

**3.5. Время выполнения различает слабо** (ρ = 0.067). Медианы растут
монотонно (9.3 → 11.6 мин), но разброс внутри уровней перекрывает разницу
между ними. Существенно, что направление связи **положительное**: сильные
тратят на задание больше времени, а не меньше. Спешка — признак слабости,
а не беглости.

## 4. Настройки приватности — самый резкий маркер

| уровень | закрытое сообщество | открытое | не заполнено |
|---|---|---|---|
| 0 | 33.0 % | **61.2 %** | 5.8 % |
| 1 | 61.3 % | 37.7 % | 1.0 % |
| 2 | 79.3 % | 20.4 % | 0.3 % |
| 3 | **88.3 %** | 11.7 % | 0.0 % |

Одна эта переменная разводит крайние уровни почти зеркально: 61 % против
12 % в пользу открытого сообщества. Для короткой диагностики это самый
экономный показатель из всех найденных.

## 5. Небезопасные ответы: высокая специфичность, низкая чувствительность

| небезопасный ответ | ур. 0 | ур. 1 | ур. 2 | ур. 3 |
|---|---|---|---|---|
| «пусть все посмотрят этот сайт» (переслать ссылку) | 10.4 % | 2.5 % | 0.6 % | 0 % |
| «пусть все напишут свои номера телефонов» | 7.9 % | 3.3 % | 1.4 % | 0.4 % |
| «расскажу об этом в сообществе» (разглашение) | 18.2 % | 16.3 % | 10.7 % | 6.6 % |

Такие ответы **почти не встречаются** выше нулевого уровня — но и внутри
нулевого их даёт лишь меньшинство (8–18 %). То есть это маркеры высокой
специфичности и низкой чувствительности: они надёжно указывают на
проблему, но их отсутствие ничего не гарантирует.

Практический смысл: по этим пунктам нельзя строить шкалу, но можно
строить **триггер тревоги** — единичный такой ответ уже повод к
вмешательству.

## 6. Латентная структура: один содержательный конструкт, а не три умения

**Числовой блок общей структуры не имеет.** KMO = 0.51 — ниже
общепринятого порога 0.6. Параллельный анализ Хорна выделяет 6 факторов,
но все шесть лишь группируют признаки, порождённые *одним и тем же*
исходным столбцом: фактор 2 — всё про `picturechoose`, фактор 3 — всё про
`citation`, фактор 4 — всё про `savepicture`. Это артефакт конструирования
признаков, а не латентная способность.

Время выполнения, число вызовов ассистента и число сохранённых картинок
**не складываются** в общую компетентность.

**Содержательная структура есть — в ответах, а не в поведении.**
Множественный анализ соответствий (корректный аналог факторного анализа
для номинальных данных) даёт две интерпретируемые оси:

* **Ось 1** забирает 97 % инерции, но с уровнем связана слабо (ρ = −0.32):
  это ось «лог записан / лога нет», то есть та же техническая проблема
  из п. 2.
* **Ось 2** — единственный содержательный конструкт: **ρ = −0.70** с
  непрерывным баллом, при том что ось строилась **без обращения к целевой
  переменной**. Это честная внешняя валидация.

Полюс низкой компетентности этой оси собран из небезопасных решений
(переслать подозрительную ссылку, опубликовать телефоны, выбрать тип
сообщества «Бизнес» вместо сообщества по интересам).

**Вывод.** Инструмент измеряет **одно** — осторожность и осмысленность
поведения в сети. Разделение на три умения (настройки, личные сообщения,
комментарии), заявленное в первой версии работы, данными не
подтверждается: оно возникло из вырожденной корреляционной матрицы,
участия целевой переменной в анализе и произвольного кодирования
категорий.

## 7. Что это значит для методики измерения

1. **Сбой логирования у 16 % респондентов надо чинить в первую очередь.**
   Это не потеря точности «на пару процентов»: для этих людей инструмент
   не работает вообще (accuracy 0.34 против 0.593). Любая доработка модели
   даст меньший прирост, чем исправление логирования.
2. **Короткая версия инструмента возможна.** Приватность сообщества,
   число проверенных источников и нахождение верного адреса дают вместе
   бóльшую часть различающей силы. Это заметно короче полного задания.
3. **Поведенческие метрики (время, клики, вызовы помощи) слабы.**
   Соблазн измерять компетентность по «цифровому следу» вместо ответов
   данные не поддерживают: сильнейший поведенческий предиктор
   (проверка источников, ρ = 0.48) — это по сути тоже содержательное
   действие, а не темп работы.
4. **Ответы надо шкалировать по осторожности, а не по правильности.**
   Найденный конструкт — не «знает, как устроена соцсеть», а «не совершает
   рискованных действий».

## 8. Ограничения

* **Целевая переменная не внешняя.** `GGlevel` получен дискретизацией
  `GGfscore`, посчитанного авторами методики по этим же ответам. Модель
  воспроизводит их шкалу, а не независимый критерий. Отсюда же следует,
  что accuracy 0.55 — это не «точность измерения компетентности», а
  точность воспроизведения чужой шкалы по подмножеству её же входов.
* **Ключа правильных ответов нет**, поэтому варианты кодировались
  номинально. Отнесение конкретных ответов к «небезопасным» сделано
  содержательно, по формулировке варианта, а не по ключу методики.
* **Пропуск смешивает две причины** — респондент не дошёл до задания или
  сознательно не совершил действие. Логи их не разделяют.
* **Задание одно.** Все выводы относятся к сценарию «Спектакль»;
  переносимость на другие задания не проверялась.
* **Причинность не устанавливается.** Все связи корреляционные: из того,
  что сильные проверяют больше источников, не следует, что проверка
  источников делает сильнее.
